## Exact cause

The refused second point paraphrases a catalogue of networking,
subprocesses and OS signals as I/O, subprocesses and OS signals. Its own
passage has no I/O identifier. The guard correctly reports
`source_identifiers_not_preserved`, with `addedIdentifiers: ["I/O"]` and no
missing identifier. OS signal scope is preserved in this particular output;
the failure is the added I/O relationship. The first generated point is not
returned with the refused response, so its meaning is not assumed correct.

The source's separate network-I/O/IPC catalogue item and title cannot license
that substitution in passage 18. Networking is not an alias for unqualified
I/O. Accepting that alias, removing a generated point, rewriting a response,
or reclassifying the failure would not fix this defect.

## Candidate before inference

`web_networking_scope.py` wraps the v1 preparation without changing its
validators. It adds the literal source term `networking` and the finite
translation `rete` to generation guidance only when:

- the selected eligible evidence itself contains the word networking;
- it is not a reader-marked heading;
- that same passage contains neither an I/O identifier nor its already
  supported IO/input-output spellings.

The term inventory belongs to the original passage number. No neighboring,
omitted or heading-only text can activate it for a selected entry. Activation
does not depend on the page URL, asyncio name, question or passage 18. A
CSV-only selected entry and the unsupported price input receive byte-identical
messages and native schemas when this condition is absent.

Source bytes, question, complete API selection, numbering, protected
identifiers, native array limits, source/type/mechanism/OS-signal checks and
model options remain unchanged. This code runs before inference. It does
not add a validation exception, repair output or force every catalogue item
into a valid partial claim. The installed v1 source files are frozen and this
candidate is **not yet integrated into production**.
